## Alur Pengerjaan

1. **Resume:** baca `CONTINUE.md` dan ikuti urutannya (dokumen aturan, ledger progress, dokumen modul)
2. Baca `docs/design/01-AGENT-WORKFRAME.md`
3. Baca `docs/progress/STATE.md`, `SESSION-LOG.md`, `TASKS.md`, `OPEN-QUESTIONS.md` (resume kondisi terakhir)
4. Tentukan modul apa yang akan dikerjakan
5. Baca dokumen referensi sesuai modul (lihat table di WORKFRAME)
6. Jalankan Quality Checklist sebelum commit
7. Jalankan Delivery Gate antislop sebelum serah terima
8. **Update ledger progress** (lihat bagian di bawah) sebelum mengakhiri turn

## Protokol Progress — WAJIB

Setiap prompt yang dijalankan dan setiap file yang dibuat, diubah, atau dihapus **wajib** dicatat di `docs/progress/`. Aturan lengkap: `docs/design/02-AGENT-PROGRESS-PROTOCOL.md`.

Pekerjaan yang tidak tercatat dianggap belum selesai, karena agen berikutnya tidak dapat memverifikasi atau melanjutkannya.

| Aksi | File yang wajib diperbarui |
|---|---|
| Menjalankan satu prompt/sesi | `docs/progress/prompts/P-###-<tanggal>-<slug>.md` (pakai `prompts/TEMPLATE.md`) |
| Membuat/mengubah/menghapus file apa pun | `docs/progress/CHANGELOG.md` + log prompt sesi tersebut |
| Menutup turn / sesi | `docs/progress/STATE.md` + `docs/progress/SESSION-LOG.md` + blok snapshot §0 di `CONTINUE.md` |
| Task dibuat/dimulai/selesai | `docs/progress/TASKS.md` |
| Sebelum menutup sesi | `bash scripts/check-ledger.sh` → `ledger OK`, `bash scripts/check-doc-links.sh` → `BROKEN: 0`, `bash scripts/check-readme-facts.sh` → `readme-facts OK`, `bash scripts/check-api-contract.sh` → `api-contract OK`, `bash scripts/check-antislop-refs.sh` → `antislop-refs OK`, `bash scripts/check-navigation.sh` → `navigation OK` |

Percobaan login — berhasil **maupun gagal** — masuk tabel `login_attempts` dan **tidak** masuk `audit_logs` (ADR-0022): FR-AUDIT-01 "login" berarti login **berhasil**, dan username yang tidak ada pun tercatat di sana (`user_id NULL`, tanpa FK) karena itulah yang tidak dapat dilakukan `audit_logs` (C-035). Batas per username kini berujung pada **lock akun**, bukan `429`: ambang `auth.max_login_attempts` dibaca dari `system_settings` sedangkan jendela **15 menit tetap konstanta kode** (`service.LoginAttemptWindow`), percobaan yang **melewati** ambang dibalas `423 LOCKED` + header `Retry-After` dan `details.retry_after_seconds`, password yang benar saat terkunci **juga** `423` (status akun dinilai sebelum password), lock yang masih aktif **tidak** diperpanjang, dan `POST /admin/users/:id/unlock` (izin `user:update`, Administrator) hanya mempercepat pembukaan yang sebenarnya terjadi sendiri — idempoten, dengan entri `USER_UNLOCKED` ditulis **hanya** bila ada penanda lock yang benar-benar dibersihkan. Penghitung di memori (`internal/service/login_guard.go`) sudah **dihapus**; jangan menghidupkan kembali mekanisme yang menyimpan keadaan di proses. `POST /auth/change-password` **sudah berjalan** (P-034, `T-034`) dan urutannya mengikat: `old_password` diverifikasi lebih dulu (gagal = tidak ada perubahan apa pun), lalu hash baru + `RevokeAllForUser` + audit `PASSWORD_CHANGED` dalam **satu** transaksi, dan token pengganti diterbitkan **sesudah commit** — bukan di dalamnya, karena `iat` berpresisi detik dan bisa jatuh di detik yang sama dengan titik pencabutan (C-053). "Sesi yang dipakai tetap hidup" dinyatakan lewat token pengganti itu, **bukan** `keepJTI`/pengecualian per `jti`: penanda per user tidak dapat mengecualikan satu token. `POST /auth/refresh` **sudah berjalan** (P-034, `T-045`) dengan bentuk yang ditetapkan **ADR-0023**: refresh token adalah JWT kedua yang bertanda klaim **`typ: refresh`** (access token `typ: access`) dan berumur **7 hari** (`jwt.RefreshExpiry`), **tanpa penyimpanan di server** — jangan menambahkan tabel atau token buram tanpa ADR baru. Klaim `typ` **wajib**: token tanpa `typ` ditolak, middleware tidak boleh menerima `refresh`, dan endpoint refresh tidak boleh menerima `access` (keduanya `401 UNAUTHORIZED`; tanpa pemeriksaan itu satu refresh token yang bocor menjadi akses penuh selama sepekan). Endpoint itu **tidak** memakai `AuthMiddleware` karena yang dikirim refresh token di body. Pencabutannya memakai jalur yang **sama** dengan endpoint terproteksi lain (ADR-0009 butir 7 + ADR-0021 butir 6), jadi `logout_all` dan `change-password` otomatis mematikan refresh token lama. Akun nonaktif dibalas `403 ACCOUNT_INACTIVE`, dan refresh **tidak** menulis `audit_logs` (tidak ada kosakata aksinya; sesinya sudah tercatat sebagai `LOGIN`). Test: jalankan **`cd backend && make test`** — target itu memuat `.env`, menurunkan `TEST_DATABASE_URL` ke database **terpisah** `bwdcs_test` (dibuat P-024, `T-036`; `TEST_DB_NAME` mengubah nama), memakai `-p 1` dan `-count=1`, serta **menolak** DSN yang menunjuk database dev. `go test` telanjang **bukan bukti**: tanpa `TEST_DATABASE_URL` test integrasi memanggil `t.Skip` dan paketnya tetap melaporkan `ok` (C-036/C-038). Aturan modul yang sudah mengikat sejak `T-035`: **cakupan data diterapkan di dalam kueri `WHERE`, bukan di middleware** — rujukannya `ProjectScope`/`projectScopePredicate` di `internal/repository/project_repository.go`; aktor di luar cakupan dijawab **`404`** (bukan `403`, supaya keberadaan baris tidak bocor), `403` hanya untuk izin yang tidak dimiliki; owner project **selalu** anggota `project_members` dan tidak dapat dihapus dari keanggotaan; `projects.code` permanen (ADR-0017) sehingga perubahan kode → `409`. Aturan modul task yang mengikat sejak `T-038`: task **selalu lahir `open`** (`status` dari klien → `422`, bukan diabaikan); `assignee_id` dan `due_date` wajib pada `POST`; `priority` kosong → default kolom `medium`; `project_id` tidak dapat diubah (`409`); `in_progress` → `completed` **hanya** lewat `POST /tasks/:id/complete` (`PATCH` → `409`, karena izin `task:complete` terpisah dari `task:update`); `complete` pada task `completed` idempoten `200` tanpa audit baru, sedangkan pada task `open` → `409`; penanda overdue tetap **turunan** dan penyaring `?overdue=` tri-state (`true`/`false`/tidak dikirim) dijalankan di `WHERE` sebelum paginasi. Aturan modul komentar yang mengikat sejak `T-042`: `comments` **tidak menyimpan `project_id`**, jadi cakupan baca hanya boleh ditegakkan lewat pemetaan entitas → project yang tinggal **satu** di `internal/repository/comment_repository.go` (`commentEntityProjectCase`) — jangan menyalinnya ke kueri lain; `entity_type` adalah kosakata tertutup (`project`, `document`, `task`, `workflow`) tanpa alias (`workflow_instance` **ditolak** `422`), dan `workflow` berarti **instance** (`workflow_instances.id`, project lewat dokumennya); edit/hapus komentar adalah **kepemilikan**, bukan izin — `WHERE created_by_id = actor` di kueri, `404` untuk komentar orang lain walau aktor anggota project, dan **tidak ada** `comment:update`/`comment:delete` di matriks (lima endpoint hanya dijaga `comment:read`/`comment:create`; menambah pasangan izin di route = mengubah matriks tanpa ADR); daftar komentar memakai bentuk kueri `?entity_type=&entity_id=` (keduanya wajib) karena `/:entityType/:entityId` **tidak dapat** berdampingan dengan `/:id` — Gin panik saat registrasi rute (C-049); aturan isi komentar (wajib, ≤ 2000 karakter, spasi tepi dibuang) hidup di `validateCommentContent` agar `POST` dan `PATCH` tidak berbeda; dan threading **belum ada** — balasan ditulis sebagai komentar biasa (C-050). Aturan unggahan berkas yang mengikat sejak **P-045** (temuan **C-072**): perbandingan MIME membuang parameter header lebih dulu (`normalizeMimeType` di `internal/service/document_service_upload.go` — `text/plain; charset=utf-8` → `text/plain`), karena `http.DetectContentType` memang mengembalikan parameter itu untuk berkas teks sementara daftar tertutup `44-SECURITY.md` §4.2 menulis tipe medianya saja; akibat versi lamanya, unggahan `.txt` dan `.csv` **selalu** `422` walau keduanya dijanjikan `50-FSD.md` §4.2. Dua penjaga unggahan (MIME dari isi **dan** ekstensi nama berkas) berdiri sendiri, **tanpa** aturan pasangan: `.pdf` yang isinya teks bukan alasan penolakan, dan test yang menuntut sebaliknya mengunci perilaku yang tidak ada di desain. Test berkas wajib memakai nilai yang **dihasilkan** sistem yang diuji (`http.DetectContentType` atas byte sungguhan), bukan MIME yang ditulis tangan — itu cara C-072 lolos. Halaman frontend yang sudah berdiri: `Dashboard`, `Login`, `Projects` (+detail), **`Documents`** (+detail: metadata, daftar versi + unduh, unggah versi baru, arsip, dan bagian yang menyebut dirinya belum dibangun), dan **`Tasks`** (+detail). Lapisan data Documents (`services/documents.ts` + `queries/documents.ts`) mengikuti `42-API.md` §4 apa adanya; amplop `POST /documents/:id/archive` adalah `data.document` (+ `data.current_version`), sedangkan `POST /documents/:id/upload` membalas objek versi **telanjang** di `data` — jangan menyeragamkannya tanpa mengubah kontrak lebih dulu. Lapisan data Tasks (`services/tasks.ts` + `queries/tasks.ts`) mengikuti `42-API.md` §6: `completeTask` memakai endpoint sendiri (`POST /tasks/:id/complete`), penyaring overdue tri-state, dan mutasi detail **diambil ulang** karena `is_overdue`/`updated_at` dihitung server. Bukti perilaku halaman Tasks di server nyata: `python3 scripts/probe-task-module.py` (41 asersi; butuh server hidup di 8081 dan PostgreSQL; baseline pulih otomatis). Bukti tata letak di peramban sungguhan memakai `scripts/responsive-evidence.mjs` (`node scripts/responsive-evidence.mjs`, dengan kedua server hidup), bukan jsdom.
- Aturan modul dokumen (`T-037`, `42-API.md` §4) — **pakai polanya, jangan karang yang baru**: cakupan disusun satu fungsi `systemScope` (`internal/service/scope.go`) dan dipakai di `WHERE`; nomor dokumen **tidak pernah** diterima dari klien (kiriman memuat `document_number` → `422`); versi berikutnya ditentukan server (`model.NextVersion` — major bila `documents.status = revision_required`); berkas divalidasi dari **isi** (magic bytes) + ekstensi, maksimal 100 MB, dan ukuran ditegakkan saat mengalir; `checksum` = SHA-256 heksadesimal **64 karakter tanpa prefiks**; unduhan wajib diaudit (`DOCUMENT_DOWNLOADED`, transaksi singkat tersendiri) dan `entity_id` entri audit dokumen adalah **nomor dokumen**, bukan UUID; versi lama tidak pernah diubah/dihapus — imutabilitasnya kini ditegakkan **tiga lapis** (service, storage, dan trigger append-only `document_versions` dari migrasi `010`, `44-SECURITY.md` §6.1); penghapusan dokumen **tidak ada lagi** di MVP: arsip (`POST /documents/:id/archive`, izin `document:update`, `T-039`/ADR-0019) hanya mengubah `status`+`archived_at`, dan dokumen terarsip menolak unggahan versi baru (`409`) — jangan menambahkan jalur hapus dokumen tanpa ADR, karena kaskade apa pun akan ditahan trigger `23001`.
- Aturan modul workflow (`T-064`, `43-WORKFLOW.md`, `42-API.md` §5) — **pakai polanya, jangan karang yang baru**: instance **selalu lahir `version 0`** di step 1, dan setiap transisinya hanya lewat conditional `UPDATE` ber-guard **empat** kondisi (id, `version`, `status = running`, `current_step` yang sudah divalidasi) — `rowsAffected = 0` → rollback + `409 WORKFLOW_CONFLICT` dengan `details` **objek** keadaan terkini (ADR-0015), bukan `500` dan bukan pesan sukses. Aksi pada step menuntut **dua** syarat sekaligus: `role` penanggung jawab step **dan** izin `workflow_instance:<action>` (`44-SECURITY.md` §3.1/§3.3, `50-FSD.md` §5.4) — Administrator **tidak** otomatis menjadi penanggung jawab step, dan jalan pintas `OR be admin` yang dahulu ada di pseudokode §4.1 **dibuang** (temuan **C-073**): jangan menghidupkannya kembali. Izin aksi hanya ada **satu tempat**: `POST /workflows/instances/:id/actions` dipasangi `workflow_instance:read` di route dan service memilih izin dari `input.Action` setelah body divalidasi (`40-TSD.md` §6 aturan 3; route kedua dengan pola itu `PATCH /tasks/:id`). `request_revision` mundur **satu** step dengan batas bawah step 1 dan instance **tetap `running`** (ADR-0016) — jadi `status` instance saja **tidak cukup** untuk menolak: seluruh aksi wajib membaca `documents.status = 'revision_required'` lebih dulu dan menjawab `409` selama jeda revisi. Dua jalur masuk review **tidak pernah hidup bersamaan**: `/workflows/submit` hanya menerima dokumen `draft` tanpa instance, `/workflows/instances/:id/resubmit` hanya menerima dokumen `revision_required` yang instancenya sudah ada — dan re-submit **tidak** menulis baris `workflow_actions` (tabel itu hanya keputusan reviewer, `CHECK`-nya tiga nilai), tidak membuat instance baru, dan tidak mengubah definisi. Keterlambatan step adalah **turunan** (`is_overdue` dari `current_step_deadline`, ADR-0012) — tidak ada kolom status `overdue`. Definisi workflow hidup **hanya** di `/workflows/definitions` (tanpa varian `/admin/...`); `responsible_user_id` per user tetap **tidak ada** (MVP role-based, keputusan P-026) — `responsible_user_ids` pada response adalah turunan role step; notifikasi `REVIEW_REQUIRED_AGAIN` adalah tambahan modul ini di atas daftar `50-FSD.md` §8.1. Bukti perilakunya di server nyata: `python3 scripts/probe-workflow-module.py` (**46/46 asersi PASS**, lima aktor login sungguhan, baseline pulih otomatis); tanpa angka itu, klaim modul ini tidak boleh ditulis.
- Utang test yang mengikat: jalankan suite dengan `-p 1` (satu database), dan **jangan** menulis test keamanan dengan mengganti karakter terakhir base64 — ubah byte-nya (C-039, `70-TESTING.md` §3.9).

## antislop

Untuk kerja UI, copywriting, people, mobile layout, atau code comments: baca `antislop.md` (core) lalu
skill yang sesuai dengan pekerjaannya.

- Core (selalu): `antislop.md` — 38 aturan (R-01..R-38) dalam tiga tier, dial, dan Delivery Gate
- UI / visual: `skills/antislop-ui/SKILL.md`
- Copy & text: `skills/antislop-copywriting/SKILL.md`
- People (aksesibilitas): `skills/antislop-human/SKILL.md` (+ `skills/antislop-human/contrast-check.py`)
- Mobile / responsive: `skills/antislop-layoutmobile/SKILL.md`
- Code comments: `skills/antislop-code/SKILL.md`

Mode pemakaian: **`during`** sudah diputuskan user (ADR-0006 `ACCEPTED`) — filter berlaku **selama**
pengerjaan dan setiap sesi UI ditutup dengan **laporan Delivery Gate PASS/FAIL berisi bukti**, bukan
ringkasan bebas. Arah desain ada di `DESIGN.md` (**sudah terisi**; ADR-0007): dial **ENERGY 1 / RHYTHM 2
/ MOTION 1**, dan **Design Read** halaman itu ditulis di log prompt. `docs/design/11-DESIGN-DIRECTION.md`
berstatus `SUPERSEDED` — jangan diisi lagi.

**Aturan anti-drift (temuan C-065).** `antislop.md` adalah **satu-satunya** sumber daftar aturan,
tier, dan Delivery Gate. Jangan menyalin daftar itu ke dokumen proyek, jangan menulis ulang butir
Gate-nya, dan jangan mengubah nomor aturan: dokumen proyek hanya boleh **menunjuk** ke sana (pola
C-014). Salinan yang ada sebelum P-042 sudah dihapus karena terbukti menyimpang dari upstream
(`01-AGENT-WORKFRAME.md` §3.2/§5.3). Setiap rujukan `R-XX` di dokumen diperiksa
`bash scripts/check-antislop-refs.sh`.

Versi yang dipasang **dipin ke tag rilis `v3.2.12`**; provenans dan `sha256` tiap berkas ada di
`skills/README.md`, keputusannya di **ADR-0025**. Untuk memperbarui, ikuti §2 berkas itu — naikkan
semua berkas bersamaan, jangan campur core lama dengan skill baru.
